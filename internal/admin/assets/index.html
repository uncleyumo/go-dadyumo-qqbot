接入点 一个 Key + 多个 OpenAI 格式模型 = 一个接入点
        
        
        
      

      

    

  


  
  

    

      
它是谁 这部分的每一行都会逐字进 system prompt，写多少烧多少 token

      

        它在群里的名字，也是群友 @ 它、叫它时触发回应的关键词。

      

        留空走默认（话少、说得准、被惹了不急）。填「软」换成爱凑热闹那一版的口吻。
        它改的是提示词固定段里的几句话，不是这里的背景和风格——两处别写成互相打架的说法。

      

        它是什么人、什么来头。建议 ≤200 字，写太长每轮对话都在烧钱。

      

        口气什么样。举例比形容词管用：「爱用短句，偶尔阴阳怪气，从不写小作文」。

      

        每行一条建议 ≤5 条。太多了句句都像背台词，反而假。

    


    

      
怎么回话 接话时往哪儿使力。这几项是正向指导，与下面「不做什么」的禁令分开

      

        每行一条该接话时怎么接：什么话题愿意多说两句、什么话题一笔带过、
        被追问时第几轮该换姿态。以前这类指导没地方放，只能硬塞进「行为边界」，
        而那里全是禁令——模型读到一整节消极清单会当成消极人设。

      

        每行一条损人允许损到什么程度：可以损什么、不能碰什么，写清两件事。

      

        建议 80~150。超过会显得在写小作文，不像真人说话。

    


    

      
不做什么 全是禁令：什么情况不接话、什么忙不帮、什么绝不碰

      

        每行一条绝对不能做的事。一条总管原则优于一堆细则——规则互相打架时模型会懵，行为反而失控。

      

        每行一条什么情况不接话。「能闭嘴」是它像真人的第一条底线，建议至少保留一两条。

      

        每行一条⚠️ 别写一刀切拒答。「凡是求助都拒绝」会误伤真心求教的人；只写被当工具反复使唤、被恶意测试时的分寸。

    


    

      
应急话术 只在特殊场合抽一句，不进 system prompt

      

        每行一条所有模型都拒绝这轮内容时，随机发一句。留空 = 那时直接闭嘴。
        刻意与「口头禅」分开：口头禅会进 system prompt 让它日常念，这儿只在模型被上游毙掉时才抽一句。

      

        每行一条同样是全拒时发，但只在被指名艾特的那一轮用，与上面那个池子互斥、一轮只发一句。
        被 @ 了回「牛逼」像敷衍，回「在忙」才自然；没人点名却说「在忙」又莫名其妙，所以必须分开配。

    


    

      
决策与预算 决定它「说不说话、花多少钱」的旋钮

      

        

          每天最多发起多少次 LLM 调用（硬闸门），0=不限。建议 300~500。

        

          收到消息先等这么久再决定说不说话，能把一串消息合并成一轮处理——省钱第一旋钮。建议 20~45。

        

          攒批时间上叠加的随机抖动，防机械感。建议 5~15。

        

          同群还有第二台机器人时，它刚说的话单独触发本机的放行概率，与在线率相乘（0.25×白天0.9≈0.22）。1=和真人一样能触发（旧行为），0=再也不接（被 @ 除外）。建议 0.25。

        

          历史消息最多带多少 token（只管历史，人设提示词另算约 2.5K）。建议 3200；模型窗口至少 12K 才不撞。

        

          每群保留多少条近期对话（原话）。建议 30~50；长期运行靠滚动摘要，别靠无限加条数。

            改小不会立刻清空已有记忆，是随新消息到来逐渐滑到新上限。

        

          每群最多记住多少条结论（模型自己写的，比如「他叫老张，在苏州做监理」），满了按最旧淘汰。
            建议 12~30。

            ⚠️ 它和上面的短期记忆是两个独立的池子，别当成一回事：30 条原话 ≠ 24 条结论。
            实际内容在下面群卡片的「长期记忆 (n/上限)」折叠区里，可以直接编辑和删除。

        

          越高越野、越低越稳。建议 0.7~0.9。

        

          单次回复最大输出。带思维链的模型会先吃掉一部分，给太小可能回复空内容，建议 1024~2048。

      

    


    

      
发言节奏 把一段话拆成几条、按真人速度逐条发

      

        

          一段话最多拆几条。真人是连着几句一起发的，别为了显得克制就限制成 1~2 条——那反而像机器人。配上下面的「尾部加速」，5 条也不会变成一条一条慢慢爬。

        

          建议 36~60。

        

          两条消息之间的最短间隔，模拟打字犹豫。建议 800~1500。

        

          建议 2000~3000。

        

          消息每多一个字多等这么久——这是「像在打字」最明显的信号。建议 120~200。

        

          被 @、被叫名字、开发者说话时按这个系数整体提速（需在「群与开发者」里打开开发者特权）（0.5 = 快一半）。这些场景下群友在等，慢几秒就以为掉线了。

        

          多条连发时后面几条按 (1 − 该值×序号) 缩短间隔。真人发消息是越说越急的，固定间隔才是机器人感。建议 0.15~0.25，0 = 不加速。

        

          发第一条前的停顿。这个值在本项目里影响很小——攒批窗口 8 秒加模型调用（实测均延迟 4.4 秒）决定了首字最快也在 12 秒后，它淹没在里面。想调就调，不会更拟真。

      

    


    

      
在线时段 控制它每天几点愿意掺和闲聊，@ 永远不受影响

      

        

          关掉 = 全天候同频在线。

        

          默认「白天为主」：DeepSeek 的高峰是工作日 09:00-12:00、14:00-18:00，正是群里最热闹的时候，
            那会儿压活跃度只会让它不理人。

            「全天」有两档，别按名字猜：always 是 90%（日常档，仍有 10% 概率不接话）；
            always_strict 才是 100% —— 它等于关掉了在线率闸门，等于废掉「它必须能闭嘴」那条约束，
            账单随群活跃度线性涨，只用于调试或特殊场景，别长期用。

        

          被 @ 之后这么长的时间内保持实时回应，不走概率。建议 300。

        

          没命中任何时段时的活跃度。嫌它太安静往上拧，嫌话多往下拧。建议 0.2~0.5。

参数 工具轮只查池子、绝不发送消息

      

        

          还需要 config.json 里配好 MinIO（endpoint / bucket / 密钥 / 公网地址），缺一项就只走纯文本。

        

          每次工具调用会把整个池子返回给模型、直接烧 token，所以这不是「能存多少」而是「一次能扫完并选准」的上限。建议 20，上限 20。

        

          到期无条件淘汰，没有任何一张图是永久的。建议 30。

        

          每隔这么久用最便宜的模型给池子里的图重新打分，清掉垃圾。建议 6。

        

          不是「正常要走几轮」——正常一轮工具调用就够，这一轮不再有工具调用块就是交付轮。这个值只用来兜住发癫的模型。

        

          受制于 QQ：同一条用户消息最多回 5 次，文字和图共用这个额度。建议 1。

      

      

        所有发送都发生在交付轮，工具轮一次都不发 —— 所以最终轮失败重试不会把同一张图甩两遍。

开发者绑定 群里回调只给 openid，认人只能靠这张表

      

      

      

        在群里发「#认主 口令」即可自动绑定，绑定成功后建议关掉下面的开关。

      

      

        默认关。关着时，开发者的消息和群友完全一样——不过在线率闸、不豁免预算、不用快节奏、提示词里也不标身份。

          开着时它会无条件回应、超出预算也照应、说话节奏更快，并在提示词里被标出来。
          建议保持关闭：开着时你对它说话永远比群友更容易得到回应，拿这个有偏的样本判断它是不是话太多会查不出真实问题。

          这个开关不影响下面的绑定与口令——认人和特权是两件事。改完要点「保存」。
